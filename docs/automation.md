# 标签、快捷方式与 URL 调用

## 管理自定义标签

界面分为首页、应用、设置、关于；宽屏使用左侧导航。首页采用图标网格，默认已管理；四个动态视图与自定义标签同排。顶部更多或“设置 → 标签管理”可新建，长按标签可打开分组操作。应用页显示完整目录，不受首页标签过滤，右侧复选框仅作批量选择。每个应用最多属于一个自定义标签；改分类时从原标签移入目标标签。

当前自定义标签提供直接添加应用入口：搜索名称或包名，多选/全选当前结果后可“仅添加”，或显式“添加并冻结”。冻结只处理本次选中的新增集合，不扩展到整个旧标签。来自其他标签的应用会显示原归属并移入当前标签。普通添加、移动或编辑成员不执行额外的手动冻结；既有自动规则仍可按条件触发。

首页搜索后可在详情加入或移动到标签，也可长按多选后“全选结果 / 移动到标签”。全选仅选择当前搜索/筛选结果。目标可为现有自定义标签或新建标签；分类变更完整校验后提交，超限或目标消失不会部分移动。内置动态视图只选择目标集合，不作为可编辑成员分组。

单应用和多选操作提供“移出管理并解冻”。先按原权限后端确认解冻，再在操作租约内提交管理/成员移出和系统取消，最后完成回执，防止自动规则在中途重新接管。已知PM失败时不移出；写盘、系统同步或回执未知时保留恢复日志并明确提示，不冒充成功。移出会清除全部自定义标签归属及直接管理关系，并撤销对应单应用调用授权。取消标签成员、删除或替换标签只改分类，原成员仍受管理并使用未分组默认规则，保留实际冻结状态和恢复记录。

任一标签操作页的“排序与隐藏”可调整全部内置和自定义标签：用上移/下移改变顺序，勾选控制显示，点击保存生效；取消不改。至少保留一个可见标签。隐藏不删除成员、不修改回冻方式、不撤销 URL 或快捷方式。布局仅保存在本机，不写入标签导出文件；新增标签追加到末尾，删除当前可见标签后自动选择首个可见标签。

原独立标签筛选位置改成“三方 / 官方 / 已冻结 / 未冻结”。三方与官方（系统预装或更新的系统应用）按来源 OR 组合；状态中仅选已冻结或未冻结时按该状态筛选，两种都选或都不选显示所有状态。来源与状态同时生效，来源都不选则列表为空。只有点击“确定”才应用，取消不改当前筛选。

自定义标签独立勾选锁屏、划卡，可多选，零选不自动回冻。划卡指移除最近任务卡片，任一条件满足即可触发，不等待锁屏延迟。四个内置动态视图不再编辑回冻模式；标签管理中单列“未分组默认规则”，保留旧“全部”模式。旧“已管理/已冻结/可用”模式退休，不迁移为应用覆盖规则；旧退出位继续移除，标签配置仍保留锁屏和划卡条件。

应用始终采用所属自定义标签规则，否则使用未分组默认规则，页面、URL和快捷方式来源不再覆盖。旧显式来源会话也按当前归属重新判断；移动标签或修改模式即影响现有活动会话，未决后端租约仍保留取消收尾。系统在配置同步、启动解锁和锁屏事件检查一次受管集合，包状态和卡片移除按目标补充检查；没有周期轮询，窗口刷新不扫描全部成员。

划卡监听实际最近任务成员从存在到移除的转换，覆盖不经过原 ATMS.removeTask 入口的移除路径；无实际移除、移除后重新加入和容量整理不触发。只有同应用最后一张卡片移除时才触发；其他同应用卡片、可见分屏/画中画、媒体/通话等保护条件仍可阻止冻结。划卡事件/倒计时不写盘，重启不复活旧手势；自动采用已有应用不使用“启动失败”回滚计时。

“解冻标签”只解冻成员，不批量启动应用。动态页批量操作也逐应用使用所属规则，因此在“全部”解冻手动标签成员，不会再套用另一套锁屏模式。已可用成员可更新跟随会话，不重复PM启用写入；每应用只有一个活动会话。要持续解冻，请将所属标签/未分组默认规则设为手动，或显式移出管理并解冻。其他工具的PM2/3/4可直接启用为1，可靠原始状态优先恢复。

系统自动采用不写 PM；首次实际自动冻结前，先持久保存原始 DEFAULT/ENABLED 和安装身份，PM3 回读确认后才公开为恢复记录。单应用解冻与恢复全部、导出恢复清单通过签名桥查询，并再次核验当前用户、UID、签名、首次安装和实际 PM3；不会覆盖待核对或安装身份变化的本地记录。未知写入继续保留未决租约，不把候选恢复记录当作已确认。系统恢复记录最多500条，满额时拒绝新增冻结，不静默覆盖历史原始状态。

首页和详情的“解冻”不启动应用，“打开应用”是独立动作；两者均显示并采用所属标签/未分组默认规则。单应用、标签和动态视图URL及快捷方式只决定目标集合，不另行覆盖模式。核心UID、当前桌面/输入法/电话及授权链默认保护，可逐包高危放行；恢复未放行或已撤销放行的包时使用持续解冻，不强制建立被保护拒绝的自动会话。

## 高危放行列表

在设置进入“高危放行列表”。默认没有放行项；列表展示当前已放行的应用名称和包名。管理弹窗可按名称或包名搜索受保护应用，查看核心/共享UID或关键角色等拦截原因，逐项勾选并“保存放行”；搜索不会丢失勾选，取消不修改设置。已卸载的历史项仍可从列表移除。

“主题壁纸”是 `com.android.thememanager`，原来命中轻冻的核心UID保护。勾选该项并保存后，可使用原 Root/Shizuku 冻结、URL、快捷方式及已设置的标签自动规则；放行本身不把应用加入受管集合。仅放开这个包，不同时放开同一共享UID的其他应用。放行也不会跳过安装身份、未决租约、隐藏/挂起限制、媒体/最近任务保护及 PM 回读。

冻结高危应用可能影响系统界面、桌面、输入法、电话或授权通道，风险由用户自行承担。该设置仅解除轻冻自身保护，系统PM和ROM仍可能拒绝操作。平台包 `android` 不提供通用冻结入口，轻冻本体仍使用专用开关。

撤销放行会取消相关自动会话和计时；未决后端操作保留取消收尾，不自动解冻已经禁用的应用。恢复基线仍保留，撤销后可以解冻或通过恢复清单恢复。放行集合只保存在本机设置和签名系统规则快照中，不写入标签导出或导入授权。

高危列表需协议7，所属规则与安全移出需协议8；0.7.0保持该协议。更新后重启，确认系统模块0.7.0；旧模块会暂停不兼容自动规则并提示更新，不能静默继续旧来源覆盖逻辑。未连接系统模块时，Root/Shizuku手动路径仍可使用本机逐包放行。

外部直接启用的待确认记录明确保存为“启用请求意图”，不冒充其外部原始状态；成功持续解冻后清除记录，确认临时启用后才建立新的ENABLED基准。“恢复全部”不接管外部未决请求。未知结果继续保留互斥租约，避免重试造成冲突。解冻成功同时要求PM回读匹配、实际enabled且未suspended，DEFAULT0但manifest仍禁用不会虚报可用。

## 导入和导出

长按标签或点击“标签操作”可通过系统文件选择器导入/导出 JSON，不需要全盘存储权限。自定义标签导出其完整配置，不受搜索/二级筛选影响。导入会完整校验并展示预览：默认合并，同 ID 更新、新 ID 添加；名称或成员冲突不会静默覆盖。也可明确选择替换全部自定义标签。

四个内置动态标签均可导出完整成员快照，同样忽略搜索和二级筛选。快照可记录最多10000个应用/4 MiB，因此“全部”或“可用”包含较多系统包时也能导出。文件保存的是点击导出时已经固定的成员集合，等待文件选择器期间不会改成另一个标签；页面重建丢失待导出内容时会取消并提示重试。

内置快照保持version2格式，新导出的动态视图mode为手动0，因为集合中应用可能属于不同规则；导入后是手动静态标签，可再设置。旧version2的mode仍兼容导入，旧version1无mode快照按原兼容规则具体化，均不修改内置视图定义。

内置快照采用 `type=app-tab-snapshot` 格式，导入时转成名为“全部快照”等的静态自定义标签，不修改原四个动态视图。导入仍遵循500成员管理上限；超过500或包含只读系统平台包 `android` 的完整清单可导出，但需缩小范围/移除该平台项后才能作为管理标签导入。不自动删项，不导入恢复所有权。

文件最大 1 MiB、最多 100 标签、500 个不同成员；系统规则快照另有 128 KiB 上限。保存、模式切换和保护开关都会预先验证候选快照，失败时保留原设置。

本机管理集合和标签在0.6.0第一次管理写入时迁移为单个原子快照。读取旧配置不写盘，迁移失败不以空配置代替；标签导出格式继续兼容。替换标签会保留旧成员为未分组，因此新旧管理应用合计超500项会先拒绝，需显式移出不再管理的应用。旧版不会读取迁移后的新快照，不保证无损降级；回退前应导出标签及已管理清单。

以下仅是格式示例，`com.example.player` 不表示设备上已安装的应用：

```json
{
  "version": 1,
  "tags": [
    {
      "id": "123e4567-e89b-12d3-a456-426614174000",
      "name": "影音",
      "mode": 1,
      "packages": ["com.example.player"]
    }
  ]
}
```

`mode`采用位掩码：`0`不自动、`1`锁屏、`4`划卡、`5`锁屏和划卡。新设置只使用这四个值。旧文件的离开应用位`2`在读取时移除：`2/3/6/7`依次变为`0/1/4/5`，`-1`按已迁移的原默认值具体化；未知位仍拒绝。标签ID稳定，改名不变。导出不含URL/快捷方式令牌、Root/Shizuku授权、运行中会话、恢复所有权或本体冻结设置；导入不执行PM。

## 创建标签快捷方式

四个内置标签的操作页与自定义标签详情均提供“冻结标签”和“解冻标签”快捷方式。请求后按系统桌面提示固定。快捷方式独立于 URL 总开关、排序与隐藏；自定义标签改名仍通过稳定 ID 定位当前成员，删除标签后旧快捷方式不可执行。原有单应用“解冻并打开”快捷方式继续使用。

## 使用 URL

先在设置中开启“允许 URL 调用”，再从任意标签操作页或应用详情复制冻结/解冻 URL。链接包含目标专属令牌，可在相应页面撤销；撤销后需重新复制。冻结和解冻使用同一目标授权，不授予其他目标权限。

路由格式（花括号表示需要由应用生成的值）：

```text
lightfreeze-yudigaga://v1/freeze?tag={tagId}&token={token}
lightfreeze-yudigaga://v1/unfreeze?tag={tagId}&token={token}
lightfreeze-yudigaga://v1/freeze?package={packageName}&token={token}
lightfreeze-yudigaga://v1/unfreeze?package={packageName}&token={token}
```

无需手工填写令牌，直接使用应用生成的完整链接。自动化工具如支持 Intent，使用 `android.intent.action.VIEW`，数据填复制的 URL，包名指定 `io.github.yudigaga.lightfreeze`。这样可明确选择本工具来处理自定义协议。

内置动态标签使用 `tab=all`、`tab=managed`、`tab=frozen`、`tab=available`，例如 `lightfreeze-yudigaga://v1/freeze?tab=frozen&token=<本机生成的令牌>`。`unfreeze` 为解冻操作。自定义标签继续使用 `tag=<UUID>`，单应用继续使用 `package=<包名>`。每条链接只允许一个目标参数。

内置标签在执行时固定本用户的完整成员集合，不受搜索、二级筛选、排序或隐藏影响：全部为已安装目录，已管理为当前管理集合与已安装目录交集，已冻结为 PM 状态2/3/4，可用需 PM 状态0/1且确实启用、未挂起。冻结“全部”也会跳过保护项，不承诺所有系统应用可冻结。

URL 默认关闭，目标必须是已管理应用、存在的自定义标签或四个已知内置标签，仍经过保护名单、原始状态所有权、系统租约和 PM 回读。它不能执行 shell、指定其他用户、读写文件或传入外部回调；未知/重复参数、片段及畸形编码会被拒绝。复制链接会标记剪贴板内容为敏感，配置导出不带令牌。删除自定义标签会撤销其 URL 与快捷方式令牌；随后重新导入相同 ID 不恢复旧授权。

URL与快捷方式使用透明、无动画、不可交互的短期Activity，结束只显示一次简短Toast，无进度页或结果对话框，不创建常驻服务。冻结按执行后实际PM状态统计，已冻结项也计入：全部确认冻结显示“已冻结”，否则显示“已冻结 X 个，未冻结 Y 个”；无法读取或安装身份改变的项目另计为未确认，空集合不显示已冻结。本体回冻未确认时追加提示。详细失败按应用记摘要，另记批次数量、成功数和elapsedMs，均不含原URL或令牌。Root/Shizuku仍需真实授权，外部工具的首次授权界面不由轻冻控制。冻结本体后的URL使用下节系统入口；本包桌面快捷方式仍不能唤醒禁用本体。

本版继续要求系统协议8报告所属规则及移出配置持久化回执能力。旧模块先暂停自动模式并提示重启，手动恢复继续遵守原租约和保护；不会绕过最近任务保护或把“配置已持久化”等同于后端租约已完成。更新后确认系统侧显示0.7.0。

## 本体被冻结时使用 URL

先更新APK并重启系统，确认设置中“本体冻结后的 URL 系统入口已就绪”；选择并授权Root/Shizuku，开启URL并复制需要的链接，再使用专用本体冻结开关。此流程会同步URL开关和有效目标令牌摘要到系统私有AtomicFile，绑定当前已解锁用户及模块签名/UID/安装/版本；不读取App私有目录，不把令牌放入标签导出。

已加载系统对合法URL临时启用本包，启动透明URL Activity，再由原App重新校验本地URL授权并走原控制器。每次调用有唯一delivery和独立Activity身份，BEGIN覆盖整批，所有并发END确认后才安排本体回冻；目标未决租约、持久化失败或十分钟内未收到完成回执时保留启用并报未知，不在批次间隙强杀。冻结前保存checkpoint，主界面“保持本体解冻”会持久取消待回冻且不取消目标规则。

普通无结果ACTION_VIEW调用可使用原URL；窄PM查询投影仅对有效自包URL返回自己的组件，不改变全包enabled状态。兼容自动化工具可明确填写：

| 字段 | 值 |
|---|---|
| Action | `android.intent.action.VIEW` |
| 包名 | `io.github.yudigaga.lightfreeze` |
| 类名 | `io.github.yudigaga.lightfreeze.ui.UrlActionActivity` |
| Data | 从轻冻复制的完整URL |

调用者的 ActivityOptions 不读取、解包或转发；它们只作为调用附带信息被丢弃，普通显示和动画参数不会阻止有效命令。系统始终用固定组件、固定用户和干净 Intent 执行，不继承调用者的后台启动、远程动画或任务权限。不支持以for-result、批量Activity、Profiler或复杂授权/文档 Intent 代替普通命令。调用器若额外检查整个包enabled并拒绝发送请求，系统入口收不到调用，需改用直接发送Intent的工具/模式。不为此伪造全包状态或启用任意其他组件。返回仅代表系统已接受命令，实际结果由后续Toast/逐项日志表达。

本体桌面快捷方式仍不能唤醒禁用包；Root/Shizuku初次授权及服务就绪仍须设备实际满足。冷启动等待Shizuku Binder最多2秒且同后端请求仅尝试一次，断线/权限失败不会切换权限源。Main正常打开先KEEP确认后才允许改凭据/标签；冻结准备期间有全局代次屏障，迟到回执不会覆盖新准备。数据清除/重装/更新会使旧系统授权失效。禁用模块下次开机是否仍注入及具体ROM的Hook/解析器行为未做真机验收，保留外部恢复方式。

单应用和自定义标签只按包加载目录。批请求仅在新协议配置令牌确认后复用本次STATUS/SYNC回执，后端对象只活到请求结束；系统控制器重建或策略变化会使旧令牌失效，明确未授予租约的配置不匹配才重新同步一次，未知执行结果不自动重试。旧模块不支持令牌时逐项同步；更新后重启系统可启用新路径。最近任务最终检查、身份和PM回读仍逐项执行。具体速度取决于设备PM、存储及后端，尚无修改后真机计时。

本体冻结确认页单独提供可复制的外部恢复命令，按本次原始状态选择 `pm default-state` 或 `pm enable`，并填写当前用户。例如用户0原状态为DEFAULT时，在已授权ADB执行 `adb shell pm default-state --user 0 io.github.yudigaga.lightfreeze`；原状态为ENABLED时使用 `enable`。Root终端去掉 `adb shell` 前缀。原“导出恢复清单”只包含目标应用，不包含本体。命令语法依据AOSP `PackageManagerShellCommand` 的 enable/default-state帮助；ROM是否允许实际执行仍须设备验证。

## 最近任务保护

设置中的“最近任务保护”默认关闭。开启后，应用只要仍在系统最近任务列表中，就跳过自动回冻、手动冻结、标签冻结和 URL 冻结；即使当前不在前台也保护。从最近任务移除后，再按规则与延迟判断。

此功能由 API102 系统模块读取最近任务并监听增删事件，不轮询，不向管理 App 新增读取任务或后台服务权限。列表被截断、用户未解锁、字段/权限不支持等情况会拒绝冻结并显示原因。媒体/通话保护与该开关独立。

安装更新后需重启以加载新的系统模块。若界面显示系统侧版本或能力未就绪，开启该保护时会先暂停旧自动规则，避免旧模块忽略新设置；持续解冻仍按安全流程执行。真实 ROM/框架查询、桌面与跨重启行为尚需设备验证。
